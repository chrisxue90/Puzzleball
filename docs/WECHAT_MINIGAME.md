# 微信小游戏开发与发布规范

## 不可违反的项目要求

> **必须符合微信小程序开发规范。**
>
> **微信游戏端必须符合微信小游戏开发规范。**

这两项要求属于项目硬性验收条件。任何改动只要导致微信开发者工具无法正常编译、上传目录缺少运行时文件、使用未声明的隐私接口、违反平台内容规则或无法通过审核，就不能合并或发布。

## 多端架构

- `app/` 与 `public/`：网页/PWA 版本。
- `wechat-game/`：微信小游戏完整上传目录，开发者工具必须直接导入此目录。
- `wechat-game/shared/game-core.js`：网页版与小游戏共用的唯一玩法规则源码。
- `miniprogram/backend/`：独立部署的自有服务器后端，不进入小游戏代码包。
- `project.private.config.json`：开发者个人配置，必须保持在 `.gitignore` 中。

小游戏使用 Canvas 2D 和 JavaScript，不加载网页版本，也不依赖 DOM、`window`、浏览器 `localStorage` 或 Service Worker。共享核心不得直接调用 React、Canvas 或 `wx`，运行时适配由两个客户端分别完成。

## 当前合规基线

- 微信端入口为 `game.js`，全局配置为 `game.json`，项目类型为 `game`。
- 游戏运行代码、共享核心和本地资源全部位于 `wechat-game/`。
- 小游戏运行时引用不得越出 `wechat-game/`，避免开发者工具上传时漏包。
- 当前不发送网络请求，不要求登录，不收集个人信息。
- 游戏进度、设置与最高分仅通过微信本地存储保存在用户设备上。
- 音效在支持时通过本地 Web Audio 合成；不可用时静默降级。
- 触感反馈仅在用户开启后调用，失败不得影响核心玩法。
- 不包含广告、支付、诱导分享、用户生成内容或远程动态代码。

如果后续增加登录、广告、支付、联网排行榜、分享、分析统计或用户内容，必须重新进行权限、隐私、域名、安全、内容和类目审核。

## 开发与打包规范

1. `wechat-game/` 必须可从干净仓库独立导入和编译，不得依赖预先复制或生成共享核心。
2. 必须保留 `game.js`、`game.json` 和 `project.config.json`。
3. `project.config.json` 的 `compileType` 必须为 `game`，AppID 必须属于微信小游戏。
4. 所有 JSON 必须是合法 JSON，不得包含注释、尾随逗号或 JavaScript 表达式。
5. 所有运行时相对引用必须解析到 `wechat-game/` 内部。
6. AppSecret、上传私钥、数据库密码和管理凭据不得进入小游戏目录或 GitHub。
7. 禁止远程下载并执行 JavaScript，禁止 `eval` 和 `new Function`。
8. 网络请求只能访问后台配置过的 HTTPS 合法域名，并处理超时、失败和弱网状态。

## 玩法与体验要求

1. 棋盘必须保持严格的 `9 × 9` 等分布局，触控命中与绘制格子必须使用同一尺寸计算。
2. 彩球必须保持高对比度，尤其区分深蓝紫与亮玫红、黄色与绿色、红色与橙色。
3. 网页版和小游戏必须调用同一份 `wechat-game/shared/game-core.js`。
4. 核心玩法在关闭声音、关闭震动或断网时必须仍可使用。
5. 必须在 iOS 与 Android 微信客户端上进行真机验证。

## 本地调试

1. 安装最新版微信开发者工具。
2. 选择“导入项目”，目录选择仓库中的 `wechat-game/`，不要选择仓库根目录。
3. 确认项目类型是“小游戏”，并使用已注册的小游戏 AppID。
4. 点击“编译”，确认不再出现寻找 `game.json` 的错误。
5. 试玩新游戏、继续游戏、寻路、连五消除、最高分、声音、震动和闪电模式。
6. 使用“预览”和“真机调试”在至少一台 iOS 与一台 Android 设备上测试。

提交代码前运行：

```bash
pnpm check:all
```

其中 `pnpm check:wechat-game` 会验证入口、JSON、AppID、运行时引用边界和共享核心复用关系。

## 提审前检查清单

- [ ] 微信开发者工具可以直接导入 `wechat-game/` 并无错误编译。
- [ ] 使用已认证主体的小游戏 AppID，并选择与内容一致的游戏类目。
- [ ] 所有运行时文件和资源都位于 `wechat-game/`，没有越界引用。
- [ ] 主包体积、资源体积和基础库版本满足上传页面显示的当前限制。
- [ ] 没有未配置的网络域名、HTTP 明文请求或远程动态代码。
- [ ] 实际隐私接口调用与用户隐私保护指引一致。
- [ ] 名称、图标、简介、截图、软著及其他审核材料已经准备完成。
- [ ] iOS、Android、不同屏幕尺寸、离线和低性能设备均完成核心流程测试。
- [ ] 已完成代码质量检查、预览、真机调试和体验版验收。

平台规则会持续更新。每次提审前必须重新查阅微信官方文档与开发者工具中的当前限制，不能只依赖本文中的历史结论。
